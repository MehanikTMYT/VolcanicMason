## Изменения поверх предварительного порта
- Добавлена локальная категория оборудования `volcanicmason:pickaxe`: текущая зависимость MineColonies распознаёт кирки через отсутствующее в .81 действие `pickaxe_dig`. Volcanic Mason использует тег PICKAXES + TOOL-компонент и существующую таблицу уровней MineColonies, не меняя глобальную категорию. Исправлены выбор инструмента, его удержание в инвентаре и стандартные Tool-запросы с новым типом. Проверка `isCorrectToolForDrops` сохраняет ограничения материала инструмента.
- Точная версия NeoForge для сборки: .81; Java toolchain 25.
- Исправлен namespace записи в `ModJobs.jobs`: `volcanicmason:volcanic_mason`.
- Регистрация ModeSettingFactory перенесена в очередь common setup: таблицы фабрик MineColonies используют несинхронизированные HashMap.
- Первый поиск позиции генератора возвращает найденную позицию сразу, без лишнего цикла AI; удалена дублированная обработка cobble.
- Изменение и сброс дневного счётчика вызывают markDirty. В NBT сохраняется miningDay: повторный onWakeUp при загрузке гражданина в тот же день больше не обнуляет добычу. Старые записи без miningDay сохраняют счётчик при первой загрузке и получают маркер текущего дня; сброс происходит при следующем пробуждении в другой день колонии.
- Повреждённый индекс режима в NBT/пакете безопасно заменяется COBBLESTONE; значения и порядок четырёх режимов не изменены.
- Установка лавы проверяет занятость позиции после подхода и возвращает пустое ведро только после успешной установки блока. Убрано повторное уменьшение стека. Разрешено замещение воды, которая заполняет генератор после добычи обсидиана; твёрдые и waterlogged-блоки защищены.
- Datagen run исправлен на serverData в соответствии с GatherDataEvent.Server.
- Добавлен отдельный QA source set и JAR; тестовые классы не входят в релиз.

Сохранены исходные исследования, рецепты, локализации и десять blueprint-файлов. Предварительный порт уже включал Identifier, новые сигнатуры NBT, block/item registration, capability API, новый item model и единственные числа в путях recipe/tag.

## Воспроизводимость
Команды выполняются на NL из worktree:

```sh
export JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64
./gradlew build qaJar --offline --no-configuration-cache
python3 qa/resources.py
python3 qa/server-smoke.py server-final3
python3 qa/server-smoke.py server-restart3
python3 qa/client-smoke.py
```

`qa/server-smoke.py` использует только `run/server` данного worktree, loopback-порты 25941/25942 и собственный мир vmqa-world. Повторный запуск проверяет сохранённую колонию. Для нового прогона нужно переместить прежний тестовый мир. QA JAR нельзя устанавливать в игровой сервер: он создаёт стенд в отдельном тестовом мире.

Точные SHA-256 реально загруженных локальных зависимостей записаны в `evidence/runtime-artifacts.json`; `dependency-builds.json` содержит также коммиты соседних репозиториев и их build/libs (эти файлы не следует путать с mavenLocal-артефактами).
SEMI/EMI загружается транзитивно через локальную зависимость даже при `-PrunWithEmi=false`.

## Методика и пределы проверки
Серверный probe создаёт настоящие объекты колонии, здания и гражданина через MineColonies API. Production-обработчики decide/harvest/placeFluid вызываются рефлексией; добыча, инструмент, дропы, статистика, счётчик и инвентарь не подменяются. Гражданин находится рядом с блоком, AI отключён для детерминированного стенда. Это проверка обработчиков игровых действий, а не полный автономный рабочий день: задержки, навигация через blueprint, доставка курьером и сон требуют отдельного сценария.

Отдельно проверяются реальные тики жидкости. Сохранение проверяется завершением процесса сервера и запуском нового процесса с тем же миром, а не только round-trip объекта в памяти.

## Клиент и оставшиеся проблемы
- Клиент на Xvfb :97 с программным OpenGL дошёл до главного меню, где видны Minecraft 26.1.2 и NeoForge 26.1.2.81 (9 mods). `evidence/client-final.png` просмотрен; `client-final.log` сохраняет полный вывод. Процесс завершён ограничителем времени, штатный выход не проверялся.
- В клиентском логе **7 ошибок моделей стеллажей MineColonies**: отсутствует loader `domum_ornamentum:materially_textured`. Ошибок загрузки моделей с namespace volcanicmason не найдено. Это проблема используемого сочетания зависимостей; их исходники не менялись. Клиентский запуск поэтому является частичным PASS, не полной клиентской приёмкой.
- **Блокер:** MineColonies загружает ClientLevel на dedicated server при входе владельца в колонию; игрок отключается. См. CLIENT_BLOCKER_RU.md.
- GUI здания, переключение режимов мышью, отображение рецептов, размещение стилей Build Tool и полноценная игра в колонии не проверены.
- На сервере логируется проблема DebugFile/Netty kqueue (OSX/BSD native probe на Linux); она не завершает процесс. Есть предупреждение о низком свободном месте на NL. Сохранение и штатная остановка проверяются отдельно.
- Полный автономный рабочий день с навигацией, доставкой курьером и сном, опция no_research и импорт реального мира 1.21.1 остаются для ручной/отдельной интеграционной проверки.
- В логах ранних запусков сохранены ошибки тестового стенда (имя style pack, готовность чанков, попытка сериализовать Tool через фабрику вместо его статического сериализатора). Фактический дефект распознавания кирок подтверждён в `server-probe-4.log` и исправлен локально в моде; успешная добыча всех четырёх материалов впервые подтверждена в `server-probe-5.log`. server-restart2.log выявил реальный сброс счётчика при загрузке гражданина: CitizenData.updateEntity вызывает CitizenSleepHandler.onWakeUp даже без сна, далее вызывается обработчик здания. Исправление ограничивает сброс новым днём колонии. Для приёмки использовать итоговые логи из таблицы результатов.
